# LeetCode Tracker OAuth Backend

This is the FastAPI backend for the LeetCode Tracker Firefox Extension. It securely handles the GitHub OAuth Authorisation Code Exchange (PKCE) to prevent the extension from exposing your GitHub Client Secret in the browser.

## 🚀 How to deploy on Render

Deploying this backend on Render is completely free and takes just a few minutes.

1. **Push to GitHub**: Make sure this `backend` folder (and the rest of the extension repository) is pushed to your own GitHub repository.
2. **Create Web Service**: Go to the [Render Dashboard](https://dashboard.render.com/) and click **New+ -> Web Service**.
3. **Connect Repository**: Select the GitHub repository containing this code.
4. **Configure the Service**:
   - **Name**: `leetcode-tracker-backend` (or whatever you prefer)
   - **Language**: `Python`
   - **Root Directory**: `backend` *(This is important!)*
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - **Instance Type**: Free tier is sufficient.

## 🔐 How to set Environment Variables

Before completing the Render setup (or in the "Environment" tab of your service settings), you MUST add the following environment variables. Do NOT hardcode these anywhere in your repository!

- `GITHUB_CLIENT_ID`: Your GitHub OAuth App Client ID.
- `GITHUB_CLIENT_SECRET`: Your GitHub OAuth App Client Secret.
- `GITHUB_REDIRECT_URI`: The exact redirect URI generated by Firefox for your extension.

## 🛠 How to create GitHub OAuth App

1. Go to your GitHub account settings -> **Developer settings** -> **OAuth Apps** -> **New OAuth App**.
2. **Application name**: "LeetCode Tracker" (or your choice).
3. **Homepage URL**: A link to your GitHub profile or repository.
4. **Authorization callback URL**: This must match your `GITHUB_REDIRECT_URI` (see below on how to get it).
5. Click **Register application**.

## 🔑 Where to place Client ID and Secret

Once your OAuth App is created:
- **Client ID**: Copy the "Client ID" shown on the page. Place this in the `GITHUB_CLIENT_ID` environment variable in Render.
- **Client Secret**: Click "Generate a new client secret". Copy the generated secret and place it in the `GITHUB_CLIENT_SECRET` environment variable in Render. **Never put the client secret inside the extension's `background.js` or `manifest.json`!**

## 🌐 How to get your Redirect URI

In Firefox, extension IDs are generated dynamically during development.
1. Open your extension's background script.
2. Add a `console.log(browser.identity.getRedirectURL("github"))`.
3. Load the extension temporarily in Firefox, inspect the background script, and copy that exact URL.
4. Set this URL as both the **Authorization callback URL** in your GitHub OAuth App settings, AND as the `GITHUB_REDIRECT_URI` environment variable in Render.
*(Example: `moz-extension://d4400a4d-075b-4ba3-ab29-65b169bb8e7d/github`)*

## 🔗 How to update BACKEND_AUTH_URL

Once your backend is successfully deployed on Render, it will provide you with a live URL (e.g., `https://leetcode-tracker-backend.onrender.com`).

1. Open your extension's background script (`background.js` or `environment.js` if you have one).
2. Find the constant that defines the backend URL (often `BACKEND_AUTH_URL` or `API_URL`).
3. Update it to point to your new Render endpoint for GitHub auth:
   `const BACKEND_AUTH_URL = "https://your-app-name.onrender.com/auth/github";`

## ✅ How to verify deployment

Once Render says "Deploy Live", you can verify your backend is functioning properly.

1. **Verify Root**: Open your browser and go to your Render URL (e.g., `https://your-app-name.onrender.com/`).
   You should see:
   ```json
   {
       "service": "LeetCode Tracker OAuth Backend",
       "version": "1.1.0",
       "status": "running"
   }
   ```
2. **Verify Health & Config**: Go to `https://your-app-name.onrender.com/health`.
   You should see:
   ```json
   {
       "status": "ok",
       "service": "LeetCode Tracker OAuth Backend",
       "version": "1.1.0",
       "github_configured": true
   }
   ```
   *Note: If `github_configured` is `false`, double-check your environment variables in Render.*

## 🧪 How to test authentication

1. Load your updated extension into Firefox.
2. Click the "Login with GitHub" button in your extension's popup.
3. You should be redirected to the GitHub authorization page.
4. After authorizing, you will be redirected back to the extension.
5. The extension will automatically make a secure request to your Render backend to exchange the authorization code for an access token using PKCE.
6. Your extension should log in successfully!

## 🐞 How to troubleshoot OAuth

If login fails, check the **Logs** tab in your Render dashboard. The backend uses structured JSON logging without exposing sensitive data.

- **`code: missing_backend_configuration`**: You forgot to set one of the environment variables in Render.
- **`code: invalid_redirect_uri`**: The Redirect URI sent by the extension does not match the `GITHUB_REDIRECT_URI` environment variable in Render, OR does not match the GitHub OAuth App callback URL.
- **`code: client_id_mismatch`**: The Client ID used by the extension does not match `GITHUB_CLIENT_ID` in Render.
- **`code: invalid_oauth_code`**: The authorization code was already used or is invalid. Try logging in again.
- **`code: expired_oauth_code`**: The user took too long to authorize, and the code expired. Try logging in again.
- **`code: github_unavailable`**: GitHub's API is down or timing out.

Remember to double check your extension's `BACKEND_AUTH_URL` to make sure it's pointing to your Render deployment.
